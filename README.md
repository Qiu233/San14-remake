# San14 Remake

三国志14传承版的独立 Windows x64 复原项目。C# 模拟核心、原生 D3D11 地图渲染与 Godot .NET 客户端分离；支持简体和繁体中文，资源从用户本机的原版安装读取。

## 当前阶段

这是开发中的首次源码快照，尚未完成端到端复原。已接通原版地形、水面、势力覆盖、六边形网格、城市、植被和地图标签的连续渲染；游戏骨架可下令、推进时间并保存，机制覆盖仍在扩充。

**完整地图首次资源准备尚未接通。** 当前开发运行仍需要本机私有 `source_package` 及同级输入。仓库不包含这些原版资源缓存，因此干净克隆可以构建源码，但还不能独立生成完整地图启动输入。后续会将全部准备接入正式程序；不会要求发布用户运行私有研究工具。

## 代码结构

- `src/San14.Core`：状态、命令、模拟与存档。
- `src/San14.Data`：`Resources` / `Formats` 负责资源定位与格式读取，`Scenarios` / `Simulation` 负责剧本及机制适配，`Rendering` 负责渲染输入准备。
- `game`：`Application` / `Gameplay` 负责入口及会话，`ui` / `Map` 负责界面与地图，`Audio` / `Rendering` 负责媒体及渲染。
- `native/San14.Render.D3D11`：`Interop` / `Runtime` / `Device` 负责宿主及设备，`Camera` / `Scene` / `Passes` 负责相机、场景及渲染阶段。
- `build`：正式 Windows 构建及运行依赖安装。
- `runtime/windows-x64`：第三方运行组件的来源与许可；已纳入的二进制按具体路径使用 Git LFS。

## 构建

当前工具链固定为 .NET SDK 9、Godot **4.7.2 .NET**、Visual Studio 2022 C++ x64 工具和 Windows SDK。Godot 需配套 Windows .NET 导出模板。原版安装不参与编译，运行时用于读取资源。

在仓库根目录执行：

```powershell
dotnet build .\San14Remake.sln -c Release
pwsh -File .\native\San14.Render.D3D11\build-product.ps1
```

Godot 编辑器打开 `game/project.godot`。正式 Windows 导出入口：

```powershell
pwsh -File .\build\Export-Windows.ps1 -GodotConsole 'C:\path\to\Godot_console.exe'
```

导出入口构建客户端及 Native DLL，并安装第三方运行组件。默认产物写入 `.local/build-windows`。首次源码快照暂不包含音频二进制套件，当前所用套件中一项依赖的再分发许可尚未确认；完整导出需本机已有对应套件，缺失时安装步骤会提示。源码构建不需要这套音频二进制。

这些命令完成构建，不代表完整资源准备或全游戏验收通过。

## 资源与发布边界

仅提交项目源码、正式构建文件和允许发布的非原版资源。原版素材、转换缓存、原程序反汇编、私人研究文档、独立实验、离线工具和一次性脚本均不进入仓库或程序发布包。读取原版安装为只读操作。

正式运行入口使用项目自己的规则常量、C#/C++ 算法与 HLSL，不加载原版 exe、冻结 PE、解包代码段或指令解释器。渲染启动的数值输入由当前资源和这些规则生成；原资源的 shader、模型、贴图等媒体缓存继续使用。exe 及其提取物仅供本地研发和离线对照，不属于运行资源，也不随源码或发布程序分发。

实验阶段的固定粒子观察回放已从正式运行入口隔离。真实粒子发射与更新仍待实现；水面、天空、云及雾保留各自流程。上述迁移经资源独立的 CPU 接缝和正式构建核查，本次没有进行新的 GPU 或画面验收；完整地图资源首次准备仍受前述限制。

资源 override 用于地图、文本等资源。机制与参数由项目自己的实现管理。

模拟参数使用具名语义键；渲染回调和参数写入顺序使用明确的操作类型，不以原程序地址作为标识。项目旧存档中的地址形式参数键仅由版本迁移器识别，迁移后保留原值并按新格式保存。

## 架构与重构进度

源码按领域和职责分类，Core、Data、客户端与 Native 类型使用职责名称。资源路径、文件格式和跨语言接口在各自边界处理；原版机制追索与离线核对资料保存在本地研发文档中。

- **模拟与保存**：模拟 owner 统一发布命令、旬推进和报告结果。人才、迁移、出阵准备有独立阶段；玩家和基础 AI 共用命令权限与规则。地图定义、占用、成员索引、军队编组、人员归还任务、战斗结算与势力效果使用有类型状态，保留名单顺序、身份复用和延迟清理。武将任命、任职与拘押、特性、健康、已知行为、功劳周期、经验与成长通知及军队物资有独立状态；旧保存布局由迁移器转换，未知或冲突知识不擅自合并。
- **资源与规则适配**：Data 按格式读取、资源定位与规则适配分类，实际职责分离仍在继续。事件条件事实和扫描会话有独立 owner；人物来源身份目录区分逻辑查找、记录身份及占位知识，实际捕获与归还不以能力状态证明身份；军团身份与官职加成使用具名类型。世界索引按当前发布替换来源绑定，关联名单由逻辑部队持有，迁槽保留、退役释放。军队进度、返城和人物成长在候选操作中更新，保留成功发布与失败隔离；这些已改造路径退出内部 JSON 世界复制与重复全量校验。
- **客户端**：`CampaignComposition` 独立组装开局和读档会话。报告 presenter、城市与施政候选、军事预览、阵形和战法查询分离于控件绑定。人事、外交、运输、军事编辑、批量出阵与战法面板每次刷新取得独立显示视图，后续事件只保留值和逻辑身份；军事路线和多队选择草案由面板持有，战法目标资格按选中身份查询当前会话，正式下令仍由模拟核心校验。
- **渲染**：地形、G-buffer、静态模型、光照、天空、雾、水面、云、阴影、后处理和势力覆盖分别持有资源与更新状态。相机 rig 持有运动、地形资格、时钟和远景历史；军队表现 owner 持有共享附件模型池和动画历史，城市与府表现 owner 持有资源、发布版本、相机计划与绘制队列，雾归约阶段独立持有目标、程序和相机常量。场景环境持有实际消费的相机、植被和曝光值；地表细节以具名环境和风发生器状态推进，packet 布局只在导入边界处理，不建立原 Main 对象的数值 arena。帧协调器读取当前视图并保持输入发布、绘制顺序与目标恢复。

指挥官选择统一持有活动数量与有序候选，清空项保留位置和独立未知知识；来源容量只在适配和旧存档迁移处理。人物能力上限以解码后的领域数值保存，实际移动、士气、俘获和归还消费者通过 Data 目录解析人物身份。旧能力存档的记录编码只在迁移时借助对应剧本资源转换，当前存档读写不需要该来源查询。

人物第二位置和军团归属使用独立领域状态；军队接收器拥有稳定身份，空闲、退役和复用不依赖部队 ID 或源槽数值。无法解释的旧位置编码由 Data 保留为不可变兼容知识，通过独立存档扩展读写；应用组装同一存档 codec 供预览与战役会话使用，当前格式保存不读取原版资源。

人物怨恨对象、怨恨强度及忠诚／释放结算使用的独立数值也各自保存；没有已知业务含义的捕获编码由 Data 的 `CampaignSourceKnowledge` 保留，与位置兼容知识分别更新。旧字段和来源版本只在存档迁移与资源格式边界解释。

军队接收器的当前目标使用不可变目录，城市与接收器目标保存逻辑身份，未解析知识留在 Data 兼容层。空接收器、退休和复用期间的目标知识独立于活动部队；来源槽位、类别编码和固定容量只在资源适配及历史存档迁移处理。

军队当前位置统一由部队持有，行军进度、目标和下一步分别保留独立知识；运输与普通行军共用下一步状态。移动队列使用逻辑部队及稳定接收器身份，保留排序、批次和失败隔离。旧位置冲突在兼容边界保留，实际位置写入解歧；来源宽度和无目标编码不进入新领域状态。

运输部队显式持有有序航点，区分已知格、已知空项和未知选择；领域路线不受原格式五槽容量限制。原航点编码和未解析行为值由 Data 保存，当前部队与势力灭亡记录中的历史镜像分别持有兼容知识；创建、改目标及旧存档迁移在同一次发布中更新路线与兼容状态。

新建部队的逻辑身份由世界持有的持久化序列分配，退休和来源接收器复用不降低水位。候选检查不消耗身份，只有成功发布推进序列；旧存档按实际保存的逻辑引用初始化。

接收器按稳定身份维护有序的可用、保留、活动和待清理阶段，活动部队引用与退休镜像由同一领域名册持有；创建、退休和清理通过显式转换发布。来源槽位通过 Data 适配层关联，旧存档在读取时迁移。

军队生命周期聚合持有接收器和领域索引。来源头字段、辅助数组、兼容标志与来源身份由 Data 的只读兼容状态持有；资源规则在一次成功发布中合并业务更新与兼容更新，存档边界负责旧布局迁移。

军队特性名单由部队独立持有，保存有序、可重复的特性引用与未知项，领域名单不受原版槽数或编码宽度限制。原格式转换和未解析引用留在 Data，当前、退休及灭亡历史分别保存兼容知识；战法、移动、士气和返城规则从同一名单读取，无法表示的扩展名单明确返回来源规则能力缺失。

军队部署选择、当前陆阵形和水阵形独立保存，当前知识不从部署选择推断。普通野战的混乱限制使用具名行为策略；原格式的动作、类别及未解析阵形编码由 Data 兼容层保留。存档迁移覆盖活动部队、待清理镜像和势力灭亡历史，当前保存不读取原版程序。

军队士气由独立状态持有，分别保存暂定流程值和当前规则值，未知当前值不借用另一值。势力士气上限仍按当前效果动态计算；领域数值不受原字节宽度限制，原规则无法编码的扩展值明确返回能力缺失。完整战斗快照的观察与实际士气写入分别处理，避免无关结算丢失扩展值。

返城和销毁操作分别记录实际特性、伤兵与士气写入，按稳定接收器身份发布；导入原格式的观察不会自动变成领域写入。未变化的活动和退休部队保留其领域知识，中间资源结算只确认当次已发布的数值，后续回调不会重放旧写入。

默认视图的资源声明在导入边界从私有字节副本解析。相机运行 owner 接收声明身份，创建时不再重新导入全部声明；地图相机组装与阴影准备仍显式取得各自需要的独立资源副本。

详情页和地图 HUD 绑定独立本地化显示值，共享势力汇总查询，控件不查询当前世界或来源上下文。UI 音效反馈独立持有准备、取消、资源和按钮信号生命周期，应用层只连接意图与状态显示。场景音频会话统一持有声道，应用接线发布独立状态快照并管理订阅，不再维护声道镜像。

剧本浏览每行统一绑定选择定义、资源 URI 和标签；势力列表与概览输出独立只读显示结果。控件负责选择和绑定，当前君主、城市、武将、军团及头像信息在查询时生成，不保留可变世界实体。

本机存档库统一管理预览和战役槽的文件布局与读取，界面绑定选中槽和状态；活动会话管理写入 codec，底层存档保持原子替换。

建设名称目录随战役内容导入，资源身份在组装边界核对；界面只绑定只读选项与选择，不在刷新控件时读取固定数据或重复检查世界来源。

主命令面板从独立视图取得阶段、结局、城市与关、部队标签和状态文字；控件管理选择和绑定，下令权限仍由会话与模拟规则决定。

旬报告输出本地化正文和只读条目，按玩家、时期和报告流保持显示顺序；报告数据的有效性由模拟与存档边界维护。

地图概览在加载时持有只读静态内容，领地、地点和部队标记通过独立显示视图交给绘制器；选格查询只返回本地化文字。显示过程不重复计算全图哈希或验证完整世界，资源格式与内容身份由加载和保存边界维护。

三维地图的选格、城市、府和部队选择由独立状态持有者管理，刷新、轮选和标签命中使用逻辑身份；查询结果只保留显示值，不借用可变世界实体。控件和 metadata 映射选择状态，按钮与双击从同一持有者取得操作目标。

Godot 地图模型资源区分跨场景网格缓存与单次场景的材质、设施、关和城市表现历史，地图控件只借用显示结果。场景切换重建材质并读取覆盖资源，静态网格按资源 URI 和内容哈希复用；退出时按节点、城市几何、场景材质和网格缓存的各自生命周期释放。

地形资源持有者统一管理高度输入、上传网格、材质和自适应 LOD 缓存。相机变化先准备网格与拾取候选，地图控件切换节点后再发布并裁剪旧缓存；已捕获帧保留独立拾取数据。过期异步加载与正常场景退役分别按实际借用关系释放资源，资源格式解码留在 Data。

地图静态表现使用只读目录：势力领地色与标记色同次构造，建筑名称只保存显示值和来源身份。场景、纹理策略和投影配置解析成功后统一绑定控件，绘制和交互入口从同一目录读取；目录不保留可变战役世界。

地图帧捕获和城市战斗候选通过类型化世界复制分离可变集合，保留不可变资源兼容知识；旧的 JSON 领地快照及其无调用渲染分支已删除。

相机光学参数、矩阵、视锥与射线使用具名数学状态；光照、水面、雾归约和镜头后处理直接消费该状态，现有下游 packet 由格式边界生成。大气过程持有具名环境和独立天空相机，天气条件、散射与雾使用具名状态，保留季节与当前相机的发布时机。没有业务消费者的人物自由快照已删除，旧存档在迁移边界处理。

环境立方体的六面相机、天体时钟与天空参数使用独立状态；云裁剪直接消费相机，天气半径来自选中资源配置，不通过旧对象前缀传递。

云天气在导入时解码季节参数与当前条件；运行中的噪声层、散射、湿度响应、采样和动画渠道使用具名值。共享时钟与历史由云表现持有，shader 常量布局在输出边界处理。

阴影视图独立持有相机和级联历史，接收明确的视图重建状态；投射器筛选、阴影投影与普通相机的接收常量分别计算，shader 布局在打包边界处理。

季节阴影接收具名配置、选中光几何与接收样式；分组、方向通道和级联模式使用明确类型，来源布局在季节 packet 导入时解码。

季节后处理使用具名设置、独立相机与光源身份目录，选择和曝光算法不再逐帧查询原 Main 字段表；shader 常量仍在图形格式边界打包。

连续后处理的预热、景深历史、散射反馈和应用时钟由独立时间线持有，GPU 资源对由渲染器管理；资源模板与常量打包在边界完成。

后处理提交历史保留实际命令、程序和 mip 链的身份与接受顺序；绑定缓存维护资源借用、目标选择及管线模式，真实设备绑定由执行器完成。

Native 场景帧协调器独立持有相机、环境、天气与人口视图状态，分别处理资源准备和接受帧请求。各绘制阶段借用同一帧发布，资源合并由持有者操作完成；首次加载、相机接受、大气发布和人口准备保持各自执行位置。

相机几何值统一持有姿态、镜头与矩阵，拾取和场景消费者直接读取同一份状态；字节编码集中在接口边界。已接受的帧共享只读几何与编码输出，后续推进产生新帧。
相机光学设置按曝光、景深、镜头效果等职责分组；季节补丁和后处理消费者读取具名设置，保留各阶段的实际发布顺序。尚未解释的天气与兼容字段仍留在格式适配层。

日月方向、颜色和过渡历史由独立状态持有，只有完成的帧才发布到下一请求；季节资源切换保留已接受的历史。启动阴影、植被风和领地设置直接从资源导入，三层高度雾读取具名配置与波参数，不再为这些输入模拟整块原版相机内存；既有 native 编码保留在接口边界。

相机声明提供具名姿态、视锥及渲染默认值，普通消费者不再查询原 CPU 偏移；声明默认与当前光学设置独立。已支持的天气与 Fog 流程使用具名气候输入和雾状态，选中资源参数只导入一次，Cloud、Present 和雾投影读取同一结果；未知字段及未实现分支仍由各自格式与功能边界处理。

完整重构仍在进行：部分军队与人物数值状态、Data 大型上下文、其余界面借用、Native 数值 packet 和其余绘制编排，以及完整资源首次准备尚未完成。阶段性 CPU 对照与构建不替代正常客户端运行和画面验收。

游戏存档使用独立的带版本格式。与原版存档互转、多人与地图扩展保留架构可能性，尚未实现。
