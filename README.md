# San14 Remake

三国志14传承版的独立 Windows x64 复原项目。C# 模拟核心、原生 D3D11 地图渲染与 Godot .NET 客户端分离；支持简体和繁体中文，资源从用户本机的原版安装读取。

## 当前阶段

这是开发中的首次源码快照，尚未完成端到端复原。已接通原版地形、水面、势力覆盖、六边形网格、城市、植被和地图标签的连续渲染；游戏骨架可下令、推进时间并保存，机制覆盖仍在扩充。

**完整地图首次资源准备尚未接通。** 当前开发运行仍需要本机私有 `source_package` 及同级输入。仓库不包含这些原版资源缓存，因此干净克隆可以构建源码，但还不能独立生成完整地图启动输入。后续会将全部准备接入正式程序；不会要求发布用户运行私有研究工具。

## 代码结构

- `src/San14.Core`：状态、命令、模拟与存档。
- `src/San14.Data`：`Resources` / `Formats` 负责资源定位与格式读取，`Scenarios` / `Simulation` 负责剧本及机制适配，`Rendering` 负责渲染输入准备。
- `game`：`Application` / `Gameplay` 负责入口及会话，`ui` / `Map` 负责界面与地图，`Audio` / `Rendering` 负责媒体及渲染。
- `native/San14.Render.D3D11`：`Interop` / `Runtime` / `Device` 负责宿主及设备，`Camera` / `Scene` / `Passes` 负责相机、场景及渲染阶段。
- `build`：正式 Windows 构建及运行依赖安装。
- `runtime/windows-x64`：第三方运行组件的来源与许可；已纳入的二进制按具体路径使用 Git LFS。

## 构建

当前工具链固定为 .NET SDK 9、Godot **4.7.2 .NET**、Visual Studio 2022 C++ x64 工具和 Windows SDK。Godot 需配套 Windows .NET 导出模板。原版安装不参与编译，运行时用于读取资源。

在仓库根目录执行：

```powershell
dotnet build .\San14Remake.sln -c Release
pwsh -File .\native\San14.Render.D3D11\build-product.ps1
```

Godot 编辑器打开 `game/project.godot`。正式 Windows 导出入口：

```powershell
pwsh -File .\build\Export-Windows.ps1 -GodotConsole 'C:\path\to\Godot_console.exe'
```

导出入口构建客户端及 Native DLL，并安装第三方运行组件。默认产物写入 `.local/build-windows`。首次源码快照暂不包含音频二进制套件，当前所用套件中一项依赖的再分发许可尚未确认；完整导出需本机已有对应套件，缺失时安装步骤会提示。源码构建不需要这套音频二进制。

这些命令完成构建，不代表完整资源准备或全游戏验收通过。

## 资源与发布边界

仅提交项目源码、正式构建文件和允许发布的非原版资源。原版素材、转换缓存、原程序反汇编、私人研究文档、独立实验、离线工具和一次性脚本均不进入仓库或程序发布包。读取原版安装为只读操作。

正式运行入口使用项目自己的规则常量、C#/C++ 算法与 HLSL，不加载原版 exe、冻结 PE、解包代码段或指令解释器。渲染启动的数值输入由当前资源和这些规则生成；原资源的 shader、模型、贴图等媒体缓存继续使用。exe 及其提取物仅供本地研发和离线对照，不属于运行资源，也不随源码或发布程序分发。

实验阶段的固定粒子观察回放已从正式运行入口隔离。真实粒子发射与更新仍待实现；水面、天空、云及雾保留各自流程。上述迁移经资源独立的 CPU 接缝和正式构建核查，本次没有进行新的 GPU 或画面验收；完整地图资源首次准备仍受前述限制。

资源 override 用于地图、文本等资源。机制与参数由项目自己的实现管理。

模拟参数使用具名语义键；渲染回调和参数写入顺序使用明确的操作类型，不以原程序地址作为标识。项目旧存档中的地址形式参数键仅由版本迁移器识别，迁移后保留原值并按新格式保存。

## 架构与重构进度

源码按领域和职责分类，Core、Data、客户端与 Native 类型使用职责名称。资源路径、文件格式和跨语言接口在各自边界处理；原版机制追索与离线核对资料保存在本地研发文档中。

- **模拟与保存**：模拟 owner 统一发布命令、旬推进和报告结果。人才、迁移、出阵准备有独立阶段；玩家和基础 AI 共用命令权限与规则。地图定义、占用、成员索引、军队编组、人员归还任务、战斗结算与势力效果使用有类型状态，保留名单顺序、身份复用和延迟清理。武将任命、任职与拘押、特性、健康、已知行为、功劳周期及军队物资有独立状态；旧保存布局由迁移器转换，未知或冲突知识不擅自合并。
- **资源与规则适配**：Data 按格式读取、资源定位与规则适配分类，实际职责分离仍在继续。事件条件事实和扫描会话有独立 owner；军团身份与官职加成使用具名类型。军队进度、返城和人物成长在候选操作中更新，保留成功发布与失败隔离；这些已改造路径退出内部 JSON 世界复制与重复全量校验。
- **客户端**：`CampaignComposition` 独立组装开局和读档会话。报告 presenter、城市与施政候选、军事预览、阵形和战法查询分离于控件绑定。人事、外交、运输与批量出阵面板每次刷新取得独立显示视图，后续事件只保留值和逻辑身份；批量出阵草案由面板持有，正式下令仍由模拟核心校验。
- **渲染**：地形、G-buffer、静态模型、光照、天空、雾、水面、云、阴影、后处理和势力覆盖分别持有资源与更新状态。相机 rig 持有运动、地形资格、时钟和远景历史；军队表现 owner 持有共享附件模型池和动画历史，城市与府表现 owner 持有资源、发布版本、相机计划与绘制队列，雾归约阶段独立持有目标、程序和相机常量。帧协调器读取当前视图并保持输入发布、绘制顺序与目标恢复。

完整重构仍在进行：部分军队与人物数值状态、Data 大型上下文、其余界面借用、Native 数值 packet 和帧协调，以及完整资源首次准备尚未完成。阶段性 CPU 对照与构建不替代正常客户端运行和画面验收。

游戏存档使用独立的带版本格式。与原版存档互转、多人与地图扩展保留架构可能性，尚未实现。
